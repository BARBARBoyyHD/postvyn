# 2026-11-17

## Decided

- **Platform lineup swap**: X is out, YouTube (VOD + Shorts) is in. D1 (X automated or manual?) and
  OQ-3 (keep X?) closed with the swap; the resolutions are recorded in `005-REQUIREMENTS` §6 and
  `001-PRD` §14. X's automated publish never shipped, so nothing live was revoked — existing X
  channels came out `disabled` with credentials cleared.
- **Quota replaces money as the scarce resource**: YouTube meters API quota, not per-post dollars.
  Non-negotiable 6 in `AGENTS.md` was rewritten to the scarce-resource principle with the 2026-11-17
  lineup note.

## Shipped (`platform-swap-youtube`, commit `97f4bad`)

- **YouTube adapter** (`src/publishers/youtube.ts`, `youtube-auth.ts`): per-publish OAuth2 token mint
  (`invalid_grant` → `reauth_required`, never retried), resumable upload (8 MiB ranged PUTs from the
  R2 URL, park/resume on the job with one session per upload), `videos.list` read-back gate
  (processed + privacy + title as sent before `published`; disagreement → `uncertain`).
- **Short vs VOD**: square/vertical → `#Shorts` appended and the preview states the classification —
  with a recorded limit: no duration is measured anywhere (media carries width/height only), so
  classification is aspect alone and the preview says YouTube decides the rest.
- **Quota model**: constants from the Quota Calculator (read 2026-11-17) in `preview().notes` before
  any request; `403 quotaExceeded` → terminal `publish.quota_blocked` with YouTube's code, no
  retries; the estimate stored under `quota` in `publish_results.raw`.
- **Spec rules**: `youtube` in `PLATFORM_RULES` (title ≤ 100, description ≤ 5000 **bytes** UTF-8,
  tags ≤ 500, one video per upload, video-only media); X's 280/link-cost rules and the `linkCost`
  field deleted; `validate()` checks `post.title` only where a title ceiling exists.
- **Connect surface**: YouTube-only connect form (three fields + the consent-screen-In-production
  instructions), `POST /api/v1/channels` proves credentials by minting then reading `channels.list`,
  monthly token-exercise pass beside the Instagram path (named 30-day constant).
- **X removal**: adapters, registry case, env flag, connect/board/composer labels and the 402
  `cost_blocked` path deleted; grep gate returns zero hits across `src/`, `test/`, `tools/`,
  `.env.example`. `estimated_cost_usd` stays — it is generic history, and `cost.test.ts` proves old
  estimates still render.
- **Migrations `0021`/`0022`**: `channels` and `publish_results` CHECKs rebuilt to accept `'youtube'`
  (SQLite cannot ALTER a CHECK), keeping `'x'` for existing rows; the X cleanup runs above 0021's
  trigger because a trigger block must be a migration file's last statement. Verified by hand on a
  scratch local D1 seeded with legacy X rows: every row survived, the channel came out `disabled`.
- **Docs amended in the spec pass**: `001-PRD`, `003-ITA`, `004-PEP`, `005`, `runbook`, app README —
  runbook §1.2 and PEP re-verified 2026-11-17 (both say YouTube; no standalone X left).

## Cost — what was scoped out, said plainly

- No test for the YouTube token-exercise pass itself; the adapter's `invalid_grant` →
  `reauth_required` path is covered in `test/publish-youtube.test.ts`.
- No test for the legacy-row migrations; the suite applies them to an empty database, so the
  preserved-`x`-row proof rests on the manual scratch-D1 run above.
- **Every new user story is ◐, none ☑**: US-059–US-063 are code + fixtures, but ☑ means demonstrable
  in staging and there is no staging — no `wrangler login`, no deploy, no real Google consent flow.
  The first live publish per platform is what moves them.
- Short classification cannot enforce "≤ 3 min" (no duration probe); recorded as a `shortcut:` in
  `youtube-rules.ts`.
