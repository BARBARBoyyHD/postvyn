## pnpm migration (same day, later)

Switched the workspace from npm to **pnpm 10.34.9** — Cloudflare supports pnpm in Workers Builds and
it is their documented monorepo path, but the real reason is layering: pnpm's strict `node_modules`
makes an undeclared dependency a resolution error, which is ADR-014's boundary enforced at install
time instead of review time.

| Step | Result |
|---|---|
| `npm i -g pnpm@10` | 10.34.9 (corepack is broken on this box, so the `packageManager` field cannot self-provision locally) |
| root `package.json` | `packageManager: "pnpm@10.34.9"`, `engines.node >=22`, filtered scripts |
| `pnpm-workspace.yaml` | `apps/*` + `packages/*`, plus `onlyBuiltDependencies: [esbuild, workerd]` |
| `pnpm install` | 688 packages resolved, 4m14s through the FortiGate — no TLS failure |

**Two traps, both now documented in ITA §9:**

1. **pnpm 10 blocks postinstall scripts by default.** `workerd`'s binary never downloaded, so
   `wrangler` could not start. Allowlisted `esbuild` + `workerd` in `pnpm-workspace.yaml`.
2. **Next 16 generates `LayoutProps`/`PageProps` types.** Bare `tsc --noEmit` failed with
   `Cannot find name 'LayoutProps'` on a clean tree — fixed by `next typegen && tsc --noEmit`.
   This would have passed locally forever (`.next/` present) and failed on the first CI run.

Verified after install: `next` 16.4.6, `wrangler` 4.162.0 (workerd built), `better-auth` imports,
`drizzle-orm/d1` imports, `pnpm typecheck` green.

**Peer warnings left alone:** `@better-auth/core` wants `better-call@~1.4.5` / `@better-fetch/fetch@1.3.3`
and got older copies; the CLI's own tree wants `kysely@^0.28.5` and got 0.29.9. Runtime imports work, so
this is recorded rather than chased — npm's hoisting hid it, pnpm surfaced it, and it is worth revisiting
only if a Better Auth feature misbehaves at M1.

**One more catch from the first build:** `create-next-app` for Next 16 enables **Cache Components and
Partial Prefetching by default** — both of which our own docs forbid (vinext support is partial; `use
cache` is the Oct-2026 RCE surface). They are now explicitly `false` in `next.config.ts` with the reason
written above the setting, because a default is not a decision.

## Caught by the operator: `pnpm dev` was broken

I claimed the app ran. It did not — `npm run dev` returned **HTTP 500** on the scaffold page, and the
operator pushed back instead of accepting it. They were right.

```
Error: Could not find the Next.js package (next/package.json)
Resolved from: apps\frontend\src\app
Filesystem root used for resolution: apps\frontend
Error: ENOENT ... .next\dev\server\pages\_app\build-manifest.json
```

**Cause:** Turbopack resolves its filesystem root to the app directory, but pnpm links `next` into
`node_modules/.pnpm` at the **repo root** — outside that root. Turbopack will not follow symlinks past
its boundary, so it cannot see the framework it is executing. A clean `pnpm build` passed because the
production path resolves differently; only dev hit it.

**Fix:** `turbopack: { root: path.resolve(process.cwd(), "../..") }`. Verified: HTTP **200**, title
renders.

**The tempting wrong fix** was `node-linker=hoisted` in `.npmrc` — it silences this and quietly
removes the install-time enforcement of the layering boundary, which is the whole reason pnpm was
chosen. Recorded in ITA §9 so nobody reaches for it later.

**Lesson worth keeping:** a green `build` is not evidence that `dev` works. They exercise different
resolvers, and only one of them was ever run.

## `db/` — migrations and seeds, named for intent

Built the database layer as a folder of SQL rather than generated migrations:

```
apps/frontend/db/
├── migrations/  0001..0012 — one table per file, each with its indexes and its reason
├── seeds/       0001..0002 — workspaces, brands (idempotent: INSERT OR IGNORE, fixed ids)
├── check-names.mjs   enforces NNNN_<verb>_<object>.sql and NNNN_seed_<what>_into_<table>.sql
├── run-seeds.mjs     applies every seed in order, --local or --remote
└── README.md
```

**Verified on a real local D1:** 12 migrations applied · `d1_migrations` records each by name · a
second apply reports "No migrations to apply!" · seeds run three times leave 1 workspace / 2 brands ·
all 12 tables present in `sqlite_master`.

**A wrinkle worth remembering:** `wrangler d1 migrations` records the **file name** in `d1_migrations`,
so a migration name is permanent the moment it applies — renaming one makes it apply twice or never
again. That is why `pnpm db:check` runs *before* applying and in CI.

**Rejected: `drizzle-kit generate`.** It names migrations after random word pairs
(`0003_nappy_black_bolt.sql`), which is the opposite of intent-named. Drizzle keeps its role — typed
schema in `src/db/schema.ts` — while the SQL is the database's source of truth. `db:generate` was
removed from `package.json` so nobody generates a parallel, differently-named history by habit.

**My own checker was wrong first:** it banned the word "table", which would have rejected
`create_users_table` — the exact convention requested. The names were right; the rule was fixed.

## The shell, the board, and the bug that only appeared when used

M1's app shell and M2's board are built and running against real data — the last two milestones' worth
of UI that three other milestones were queued behind.

**What exists now:** a signed-in layout with the Zavron chrome (`#ff4d12` on `#0d0d0d`), a brand
switcher that writes a cookie, a seven-column board with per-column counts and composing filters, and a
post detail page that renders caption with its line breaks, hashtags as stored, media in publish order,
`ref only` on non-postable assets, and history newest-first.

**The bug is the lesson.** The first visit to `/board` returned 500, and the reason was not the board:
`ensureWorkspace` tried to create a workspace named after the user, which collided with the **seeded**
workspace's name. Two faults stacked:

1. the first user should *adopt* the seeded, memberless workspace, not spawn a second one — a solo tool
   seeds its tenant;
2. the layout and the page each resolved the session separately, so two resolutions raced.

Fixed by adopting the unclaimed workspace (with a re-read on a lost race), provisioning only as a
fallback, and `cache()`-ing the resolution per request. The general rule: **a layout and a page must not
each answer the same question**; and an idempotent-looking helper is not idempotent until it has been
called twice at once.

**Board defaults:** brands are ordered by creation, not alphabet — the first brand is the default, and a
default that moves when somebody renames a brand is a surprise. Then the tiebreak is the id, because the
two seeds share a timestamp.

**Also found:** a fresh database has no user and there is no public sign-up, so the app was unenterable.
`pnpm user:create <email> "<name>" [--remote]` now creates the first account with Better Auth's own
scrypt hasher, and a read-back assertion — an insert whose result nobody checked is an insert nobody can
trust.

**Verified:** `pnpm dev:vinext` → `/board` 200 with 4 posts and correct columns; `/posts/:id` 200;
unknown post 404; anonymous `/board` 307 to `/sign-in`; every `/api/v1` route 401 with the failure
envelope and no caption leak. Gates: lint clean · typecheck clean · **52 tests** · build green.

## M3 — the rules became data

The spec engine is in, and it is generated rather than written: `pnpm specs:generate` parses
`social/<platform>/specs.md` from the content repo into `src/lib/specs/platforms.ts`, header carrying
each platform's sha256 and the date. `pnpm specs:check` fails when the copy is older than its source, so
"the rules changed and nobody updated the app" is a build error instead of a wrong verdict.

**What the four files actually say** (parsed, not assumed): Instagram 2200 · Threads 500 with hashtags
inside that budget · X 280 with any URL counting as 23 · TikTok 2200. Hashtag bands 3–5, 3–5, 1–2, 3–5.
Media ceilings 20, 10, 4, 35.

**Two parser traps, both fixed:** ranges are written three different ways ("Hashtags: 3-5", "3-5 is
plenty", "3-5 hashtags") — matching only the first silently produced `null` for Threads and TikTok; and
the object literal was emitted by string surgery that produced invalid TypeScript, which the compiler
caught before a test did.

**Verdicts:** `blocked` only for what a platform would refuse (over ceiling, too many media, file too
large, unknown platform). Everything else warns. The counter is per-platform arithmetic, not string
length — proven by tests on the real vault caption and on X's link substitution.

**Applied end to end through the API:** created `post_m3-probe…`, added a Threads variant, PATCHed a 565
character caption → `blocked · "565 characters, threads accepts 500"`, then a 70 character one → `ok ·
remaining 430`, with `specVersion: threads@11b7a7b5bec1` stored on the row.

**Under-built, deliberately:** autosave is an explicit Save (no debounce yet), the override reason is
API-only, and there is no media picker. Recorded as partial in `tasks.md` rather than rounded up.

## The intake door: how a rendered video gets onto the board

The workflow that was missing: a video is made somewhere else, the caption is written beside it, and
neither could enter the app. Now they arrive together, through one intake that has two doors — a file
picker for the operator, and a bearer token for the agent.

**The first real push, verbatim:**

```
asset intake-probe.png -> med_c414cd0e204d (image/png)
draft post_hermes-intake-probe_mwj0i2hz · status review
  tiktok     warn · 71 chars
    ! media: 1 item(s) are not 9:16 — the platform will crop or letterbox
open http://localhost:3001/posts/post_hermes-intake-probe_mwj0i2hz
```

The warning is the system doing its job on a 1x1 probe image: the spec engine reads real dimensions out
of the PNG header, and TikTok wants 9:16.

**Decisions worth remembering:**

- **A token is a scope, not a user.** `agent_tokens` binds workspace + brand, stores only a SHA-256 hash
  (a token is compared, never replayed — the mirror of ADR-011's encrypt-because-you-must-replay), and
  resolves to `editor`. `variant.approve` is owner-only, so there is no request shape a token can send
  that reaches the human gate.
- **The caller supplies the caption.** The app has no model budget and should not pretend to write.
  Its job is to check the caption against the platform rules before storing it — which it already does.
- **A blocked caption still creates the draft.** Refusing would lose the asset and the intent; hiding it
  would teach the caller its captions are fine. It lands in `review` with `spec_state = blocked` and the
  response names the field and the counts.
- **Uploads go through the Worker at 25 MB.** Signed direct-to-R2 uploads are M6's job; the ceiling is
  named in the error instead of letting a large file time out mysteriously.
- **`activity_log` being append-only broke the test cleanup.** Deleting a workspace cascades into the
  log, and the trigger aborts. That is the rule working. The fixture now seeds idempotently instead of
  deleting.

**Not done:** the board has no link to `/intake`, and the README flow is written but the board entry point
is still missing. Both recorded as partial rather than rounded up.

## Finishing the backlog the milestones left behind

The open tasks were mostly the second half of things: autosave, overrides, media, and the importer's
honesty.

**The editor now autosaves on a 5 s debounce with a revision.** Proven against the live Worker:

```
PATCH revision 0  -> 200, revision 1
PATCH revision 0  -> 409 stale_write, storedRevision 1
PATCH revision 1  -> 200, revision 2
```

That is the whole point of the column: a slow in-flight save cannot undo newer typing. The panel also
carries the brand voice note, a media library with attach/detach and ↑/↓ reorder (order is part of the
content, not a display preference), an "accept with a reason" field on every warning, and a duplicate-to-
another-channel control.

**The importer now verifies field by field.** An import that writes four posts with the wrong caption in
all four has the right count, so counts were never evidence. Every mapped field — title, status, format,
caption, hashtags, media order — is read back and compared. First result: `7 item(s) applied and verified
field by field`.

Its limit is worth stating: it compares stored to **mapped**, so it proves the write, not the parse. A
caption-extraction bug would pass. Spot-checked separately: the About Zavron caption section is 702
characters in the vault and 610 stored, the difference being the hashtag block lifted into `hashtags`.

**Publish records now travel with a variant** when `item.json` carries a `published` block (`url`, `at`,
`id`). The vault has none today, so the path is implemented and unexercised — said plainly rather than
ticked as verified.

**The board hides closed work behind a toggle** with the count visible on the button, so history is
available and not in the way.

**The append-only guarantee got its own test** (7 cases): update and delete refused on `activity_log` and
`variant_overrides`, insert still allowed, and the cascade from deleting a workspace refused too. That last
one is the case that bites.

**Cheap wins taken:** brand `voice` and `colors` are parsed by the API instead of handed back as JSON
strings; the nav has compose and intake; `docs/identity.md` records which tables are Better Auth's and
which are ours, plus the five traps that cost time.
