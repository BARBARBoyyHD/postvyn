# `db/` — migrations and seeds

Everything that shapes the database lives here. Ordered, named for what they *do*, applied by
wrangler.

```
db/
├── migrations/   applied in order, once each, never edited after they run
├── seeds/        re-runnable, idempotent, for local development and first-run data
├── check-names.mjs   the naming convention, enforced
└── run-seeds.mjs     applies every seed in order
```

## Naming

Both folders are numbered and intent-named. The name is the only history a future reader gets, and
wrangler records the file name in `d1_migrations` when it applies a migration — **so a name is
permanent the moment it runs.** `pnpm db:check` enforces this before anything is applied.

**Migrations** — `NNNN_<verb>_<object>.sql`

```
0001_create_workspaces_table.sql
0004_create_channels_table.sql
0013_add_publishing_enabled_to_workspaces.sql
0021_backfill_channel_status_from_legacy.sql
```

Allowed verbs: `create`, `add`, `alter`, `drop`, `rename`, `backfill`, `index`, `enforce`, `split`,
`merge`. Banned words: `fix`, `update`, `changes`, `misc`, `temp`, `wip`, `stuff`, `new`, `schema` —
a name that says nothing is worse than no name, because it looks like documentation.

**Seeds** — `NNNN_seed_<what>_into_<table>.sql`

```
0001_seed_default_workspace_into_workspaces.sql
0002_seed_default_brands_into_brands.sql
0003_seed_email_password_to_users.sql        ← M1, once Better Auth's tables exist
```

Rules the checker enforces: four-digit prefix, no gaps, no reused numbers, snake_case, `.sql` only.

## Commands

```bash
pnpm db:check            # naming + numbering, before you commit
pnpm db:migrate:local    # apply pending migrations to the local file-backed D1
pnpm db:seed:local       # run every seed in order (idempotent)
pnpm db:migrate:remote   # the real database — ask before running
pnpm db:seed:remote      # same, with --yes passed through
```

Inspect what actually landed:

```bash
pnpm exec wrangler d1 execute postvyn-db --local \
  --command "select name from sqlite_master where type='table' order by name"
```

## Rules that are not style preferences

**A migration that has run is immutable.** Changing one means editing the database by hand later.
New intent → new migration.

**Seeds are idempotent.** `INSERT OR IGNORE` with fixed ids. A seed that duplicates on re-run is a
seed nobody dares run twice, which makes it useless.

**Migrations are hand-written SQL, not `drizzle-kit generate` output.** drizzle-kit names files after
random word pairs (`0003_nappy_black_bolt.sql`), which is exactly the uninformative naming this folder
rejects. `src/db/schema.ts` is the TypeScript source of truth that queries are typed against; the SQL
here is the source of truth for the database. If they drift, the isolation test and the migration
check in CI are what catch it.

**Our tables only.** Better Auth's `user`, `session`, `account`, `verification` and `rateLimit` tables
are generated by `@better-auth/cli` in M1, as their own migration — never hand-written, never edited.

## Importing the vault

`tools/importer/cli.mjs` reads `brands/<brand>/social/<platform>/queue/<item>/` and writes posts,
variants and media rows. It is a **Node CLI, not a route**, because it needs a filesystem and a Worker
does not have one.

```bash
node tools/importer/cli.mjs                                  # dry run against D:/uwi/Projetcs/Uwi's-Department
node tools/importer/cli.mjs --brand zavron                   # one brand
node tools/importer/cli.mjs --commit --local                 # apply to the local D1
node tools/importer/cli.mjs --commit --remote                # the real database — ask first
```

**Dry run is the default.** The output is the diff: posts, variants, media counts, how many assets were
excluded as review artifacts, and every problem found. A run with problems refuses to commit.

**It is idempotent.** Identity is `(brand, external_ref)` for posts and `(post, channel)` for variants,
so a second run updates instead of duplicating. Re-run it whenever the vault changes; that is the
whole migration strategy.

**Review artifacts are excluded by name.** `contact-sheet*`, `thumb*`, `preview*` are stored with
`postable = 0` and kept out of the variant's media order — otherwise a contact sheet becomes carousel
slide 2.

**Media dedupes by content hash**, so the same MP4 referenced from four platform folders is one row,
not four. That is why "24 assets" in the dry run become 18 media rows on commit.

**What it will not do:** invent a brand that does not exist in the database (it refuses and lists the
missing slugs), or import a folder with no `item.json` (it reports and skips). Both are deliberate —
a guessed brand is worse than a skipped folder.

Every commit writes its SQL to `.importer/<batch>_<brand>.sql` and appends one `import.committed`
row to `activity_log`, so a bad run can be traced without guessing which rows moved.

## Local state

`wrangler dev` and `d1 --local` keep their database in `.wrangler/state/` (gitignored). Deleting that
folder resets local data; migrations then re-apply from empty, which is the fastest way to test that
they still work.
