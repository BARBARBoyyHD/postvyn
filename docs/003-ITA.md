# Implementation & Technical Architecture — Postvyn

**Version:** 0.3 — all-Cloudflare pivot, build-ready (v0.1 was Postgres/Neon)
**Date:** 2026-Nov-15
**Status:** Draft
**Derived from:** PRD v0.1 (`docs/001-PRD.md`), amended per ADR-013…018

---

## 1. Context & Scope

This document implements PRD §5 on an **all-Cloudflare** stack: vinext (Next.js API surface on
Vite) on Workers, **D1** for data, R2 for media, Cron Triggers for scheduling. It replaces the v0.1
vault implementation (`Uwi's-Department/tools/publish`), which stays as the behavioural reference
until v1.0 ships.

**Why the pivot:** Neon's scale-to-zero made the first request after idle a wait, which is
unacceptable for a tool you open in bursts. D1 has no cold start and no idle billing.

**Technical non-goals**

- No separate API service, no second language, no microservices (ADR-001 stands).
- No analytics ingestion, no comment/DM handling, no billing (PRD v2).
- No TikTok publishing integration, now or later (ADR-008).
- No mobile app; responsive web only.
- No AI copy generation — the composer assists with budgets and voice notes, it does not write.
- No Cache Components / Partial Prerendering: incomplete in vinext *and* the surface carrying
  Next.js's October 2026 RCE history. Avoided by decision, not by accident.
- No `sharp`, no native modules — they cannot load in `workerd` (ADR-018).

## 2. Architecture Overview

```
                    ┌────────────────────────────────────────────────┐
   operator ───────▶│  Cloudflare Worker                             │
   (browser)         │  vinext app  (Next.js API surface on Vite)      │
                    │  RSC pages · route handlers · session cookie   │
                    └───┬───────────────┬────────────────┬───────────┘
   agent ───────────────┘               │                │
   (Hermes/CLI, JSON)                   │                │ signed PUT
                                        ▼                ▼
                              ┌──────────────┐   ┌──────────────┐
                              │      D1      │   │  R2 bucket   │
                              │   (SQLite)   │   │   (media)    │
                              │  jobs table  │   └──────┬───────┘
                              └──────┬───────┘          │ public GET
                                     │                  │
                     Cron Trigger ───┤                  │
                     (1 min)         ▼                  │
                              ┌──────────────┐          │
                              │ job claimant │──────────┘
                              │ + publishers │
                              └──────┬───────┘
                ┌────────────────────┼────────────────┐
                ▼                    ▼                ▼
        graph.instagram      graph.threads       api.x.com
```

**Request path.** One Worker serves the UI and the API. Each request resolves the session cookie →
`user_id` → membership rows → a `WorkspaceContext` that the repository layer *requires* before it
will run a query (ADR-014). In v0.1 this was Postgres RLS; with D1 it is application code, and the
mitigation is structural: raw D1 access lives behind a single module, and cross-workspace tests
assert that a context for workspace A cannot read B. Mutations return the `{ok, result, log}`
envelope.

**Where state lives.** D1 owns everything durable: content, approvals, schedules, publish results,
audit trail. R2 holds media bytes. There is no filesystem and no always-on process — the point of
the stack: nothing to patch, nothing to keep warm.

**Failure behaviour.** Publishing never happens inside a request. A mutation writes an intent
(approval + job row) and returns; a Cron Trigger claims due jobs and does the network I/O. A Worker
invocation that dies mid-job leaves the row `claimed` under a lease, and the next tick reclaims it.
**D1 is single-writer**, so two claimers cannot race for the same row (ADR-015); the unique index on
successful publishes is the last guard against double-posting. Platform outages surface as `failed`
jobs carrying the platform's own error text, retried with backoff up to three attempts, then parked
for a human.

**Cost/latency profile.** No cold start. Free plan: 100k rows written/day, 5M rows read/day, 500 MB
per database — orders of magnitude above this workload. The binding constraint is Worker **CPU**
(10 ms/invocation on free): fine for JSON APIs and small pages, tight for heavy SSR. Budget $5
Workers Paid if CPU throttling appears; D1 stays free at this volume either way.

### 4.2 Key Interfaces

```ts
// The only way anything reaches a platform. Adding a platform = adding an implementation.
interface Publisher {
  readonly platform: Platform;                    // 'instagram' | 'threads' | 'x'
  readonly automatable: boolean;                  // false → manual pack only (TikTok)
  estimateCost?(v: Variant): Cost | null;         // shown before spend
  publish(v: Variant, media: MediaRef[]): Promise<PublishResult>;
  verify(postId: string): Promise<VerifiedPost>;
}

type PublishResult =
  | { ok: true; postId: string; url: string; raw: unknown }
  | { ok: false; retryable: boolean; error: string; code?: string };

// Every mutation endpoint answers with this shape (matches tools/publish/publish.py --json).
type Envelope<T> = { ok: boolean; result: T; log: string };

// Tenancy is a value, not a convention: no repository method accepts a bare db handle.
type WorkspaceContext = { workspaceId: string; userId: string; role: Role };

// Spec rules are data, versioned, so an old approval can be re-evaluated against new rules.
interface SpecRule {
  platform: Platform;
  version: number;                                // bumped on any limit change
  sizes: string[];
  captionMax: number;
  countUrlsAs?: number;                           // X: 23
  hashtags: [min: number, max: number];
  imageMaxMB: number;
  maxMedia: number;
  hashtagsInFirstComment?: boolean;
}
```

### 4.3 HTTP surface

One Worker, four namespaces, one envelope. The path says who is allowed to call it, so a route's
audience is legible before anyone reads the code:

| Namespace | Audience | Auth |
|---|---|---|
| `/api/auth/*` | Better Auth's own handlers | its cookies |
| `/api/v1/*` | the board and any agent, workspace-scoped | session cookie **or** API token |
| `/api/v1/admin/*` | operator operations, `owner` role only | session cookie, role-checked |
| `/api/internal/*` | Cloudflare Cron only | `CRON_SECRET` header — never a session |
| `/api/health` | uptime checks | none; leaks liveness and nothing else |

**`/api/auth/*` is deliberately unversioned.** Better Auth owns that path and its client expects it
verbatim. It is the single exception, and it is written down rather than quietly inconsistent.

#### v1 — product surface

| Route | Method | v1 | Purpose |
|---|---|---|---|
| `/api/v1/queue` | GET | ✓ | board data — **one batched read**, never N+1 |
| `/api/v1/posts/:id` | GET · PATCH | ✓ | post + variants; PATCH re-runs spec validation |
| `/api/v1/posts/:id/variants` | POST | ✓ | add a variant for a channel |
| `/api/v1/variants/:id/approve` | POST | ✓ | the human gate: approval hash + slot |
| `/api/v1/variants/:id/publish` | POST | ✓ | enqueues a job (`dry_run` honoured) |
| `/api/v1/variants/:id/verify` | GET | ✓ | read the post back from the platform |
| `/api/v1/variants/:id/tiktok-pack` | GET | ✓ | the manual pack: caption, hashtags, ordered assets, checklist, the reason |
| `/api/v1/variants/:id/tiktok-complete` | POST | ✓ | record the operator's post URL; `published` only then |
| `/api/v1/channels` | GET · POST · DELETE | ✓ | connect / disconnect accounts |
| `/api/v1/brands` | GET · POST · PATCH | ✓ | brand kit and theme tokens |
| `/api/v1/media` | GET · POST | ✓ | list media, mint a signed upload URL |
| `/api/v1/activity` | GET | ✓ | the audit trail for a post |

#### v1 — admin surface (only what v1 needs)

The namespace exists from day one so it is a place, not a future refactor. It holds the operations
that can stop or unstick the entire workspace:

| Route | Method | v1 | Purpose |
|---|---|---|---|
| `/api/v1/admin/publishing` | GET · PATCH | ✓ | kill switch, global and per-workspace (ADR-019) |
| `/api/v1/admin/jobs` | GET | ✓ | queued / claimed / failed jobs with attempt counts |
| `/api/v1/admin/jobs/:id/retry` | POST | ✓ | requeue a parked job |
| `/api/v1/admin/channels/:id/reauth` | POST | ✓ | clear an expired-token state |
| `/api/v1/admin/users` | — | ✗ | no second user in v1 — deferred to v1.5 |
| `/api/v1/admin/billing` | — | ✗ | v2 |
| `/api/v1/admin/insights` | — | ✗ | v2 |

Anything not marked ✓ is **not built in v1**, and is listed here so nobody adds it "while they're in
there". The ✗ rows are scope protection, not a roadmap.

#### internal and ops

| Route | Method | Purpose |
|---|---|---|
| `/api/internal/cron` | POST | cron tick: claim and run due jobs. `CRON_SECRET` header, no session. |
| `/api/health` | GET | liveness + D1 reachability. Unversioned: infrastructure, not API. |

**Versioning rules.** The prefix is a promise; `/v1` freezes when v1.0 ships.

- **Additive changes never bump** — new fields, new optional params, new routes.
- **Breaking changes ship as `/v2` alongside `/v1`.** `/v1` is removed only once the board and the
  agent CLI have migrated. With one operator that is a decision, not a deadline.
- **Never mutate `/v1` in place** — no field changing type, no list becoming paginated without a new
  param that defaults to the old behaviour.
- **The version lives in the path, not the envelope.** Two sources of truth for a version is how a
  client ends up disagreeing with the server.

Every mutating route answers `Envelope<T>`. Status codes are part of the contract, because an agent
reads them:

| Code | Meaning |
|---|---|
| 200 | success (check `result`, not just the code) |
| 400 | validation failed (Zod issues in `result`) |
| 401 | no/expired session |
| 403 | role not permitted (`viewer` approving, `editor` publishing) |
| 404 | not found **in this workspace** — never leak that a row exists elsewhere |
| 409 | `reapproval_required` (hash mismatch) or `already_published` |
| 413 | upload too large — rejected before a byte reaches R2 |
| 422 | spec errors — publish refused before any platform call |
| 429 | D1 query budget for this invocation exceeded; retry with narrower filters |
| 502 | platform error, verbatim text in `result.error` |

## 5. Data Architecture

| Entity | Store | Key fields | Notes |
|---|---|---|---|
| `user` · `session` · `account` · `verification` · `rateLimit` | D1 | Better Auth's schema (`@better-auth/cli generate` → Drizzle → D1 migration) | the only tables we do **not** hand-write; identity lives here, tenancy does not. Replaces the `users` table proposed in v0.1 of this doc |
| `workspaces` | D1 | `id, name, plan, created_at` | tenant boundary |
| `memberships` | D1 | `user_id, workspace_id, role` | `owner\|editor\|viewer`; scoping hinge (was the RLS hinge) |
| `brands` | D1 | `id, workspace_id, name, handle, voice, colors json` | theme source |
| `channels` | D1 | `id, brand_id, platform, account_ref, label, status` | many per platform per brand; no secrets here |
| `channel_credentials` | D1 | `channel_id, ciphertext BLOB, iv BLOB, key_version, updated_at` | AES-256-GCM via WebCrypto (GCM tag appended to ciphertext); split out so `select * from channels` never carries it |
| `posts` | D1 | `id, brand_id, title, format, status, pillar, schedule_at, created_by` | status machine |
| `variants` | D1 | `id, post_id, channel_id, caption, hashtags json, media_ids json, spec_state, spec_version` | unit of publish |
| `media` | D1 + R2 | `id, workspace_id, hash, key, mime, bytes, w, h, postable` | dedupe by hash |
| `approvals` | D1 | `id, variant_hash, user_id, approved_at` | content-bound |
| `jobs` | D1 | `id, kind, payload, state, attempts, run_after, lease_until` | durable queue |
| `publish_results` | D1 | `id, variant_id, platform_post_id, url, raw, state` | proof, not intent |
| `sessions` | D1 | `id, user_id, expires_at` | cookie carries a signed id only |
| `activity_log` | D1 | `id, workspace_id, post_id, actor_id, action, detail, created_at` | append-only |

SQLite reality, stated plainly: `TEXT` ids (UUID strings), `INTEGER` unix-ms timestamps, JSON in
`TEXT` columns read with `json_extract()`. No arrays, no `jsonb`, no RLS, no `SKIP LOCKED`.

**Migrations and seeds.** Schema changes are **hand-written SQL** in `db/migrations/`, applied by
`wrangler d1 migrations` (configured via `migrations_dir` in `wrangler.jsonc`); first-run data is
**idempotent SQL** in `db/seeds/`. Both are numbered and named for intent, and `pnpm db:check`
enforces it:

```
0004_create_channels_table.sql                  migrations: NNNN_<verb>_<object>.sql
0021_backfill_channel_status_from_legacy.sql
0002_seed_default_brands_into_brands.sql        seeds:      NNNN_seed_<what>_into_<table>.sql
```

The name is permanent once applied — wrangler records the file name in `d1_migrations`, so renaming a
migration makes it apply twice or never again. `drizzle-kit generate` is **not** used for migrations
precisely because it names files after random word pairs; the Drizzle schema in `src/db/schema.ts` is
the source of truth for *types*, the SQL is the source of truth for the database.

**Tenancy without RLS (ADR-014)**

```ts
// src/db is the only module holding the D1 binding. Every method demands a context.
export async function listPosts(ctx: WorkspaceContext, f: Filters): Promise<Post[]> {
  return db(ctx).select().from(posts)
    .where(and(eq(posts.workspaceId, ctx.workspaceId), ...)); // injected, never omitted
}
```

Guard rails, in order of strength: (1) the binding is not exported — only context-taking functions
are; (2) a lint rule bans `db(` outside `src/db`; (3) an integration test seeds two workspaces
and asserts every list/get endpoint returns nothing from the other, including for ids passed
directly. Weaker than RLS, and written down as such: a forgotten `where` clause is now a
code-review failure instead of an impossibility.

**Job claim without `SKIP LOCKED` (ADR-015).** D1 has a single writer, so claims serialize
naturally. One statement, guarded by state:

```sql
UPDATE jobs
   SET state = 'claimed',
       lease_until = :now + 300000,
       attempts = attempts + 1
 WHERE id = (
   SELECT id FROM jobs
    WHERE state = 'queued' AND run_after <= :now
    ORDER BY run_after LIMIT 1
 )
   AND state = 'queued'
RETURNING *;
```

Zero rows returned means someone else took it. Multi-statement atomicity uses `db.batch()` (implicit
transaction); there is no interactive `BEGIN…COMMIT` across `await`, so anything multi-step is
either a batch or made idempotent.

**Other invariants (SQLite syntax)**

```sql
-- one successful publish per variant, ever
CREATE UNIQUE INDEX one_publish_per_variant
  ON publish_results (variant_id) WHERE state = 'succeeded';

-- many accounts allowed overall, but one row per (brand, platform, account)
CREATE UNIQUE INDEX one_account_per_platform
  ON channels (brand_id, platform, account_ref);
```

**D1 limits that shape the code**

| Limit | Consequence |
|---|---|
| 100 bound parameters per query | chunk inserts; never one statement per row from a loop |
| 50 queries per invocation (free) / 1000 (paid) | the board fetches in one batched read, not N+1 |
| 2 MB per row/BLOB | media bytes never enter D1 — R2 keys only |
| 30 s query duration | no analytic scans; the board paginates |
| 500 MB database (free) | not a concern: text only, media in R2 |

**Approval hash**

```
sha256( channel_id | caption | sorted(hashtags) | ordered(media ids) | spec_version )
```

Stored on the approval; recomputed at publish time. Mismatch → `409 reapproval_required` and the
post returns to `review`. Editing an approved post therefore cannot ship silently.

**Migrations.** `wrangler d1 migrations` with plain SQL files, committed and reviewed. CI applies
them to a throwaway local D1, so a broken migration fails the build and not production.

**Backup & restore.** Three layers, cheapest first: (1) **D1 Time Travel** — point-in-time restore
within 7 days (free) / 30 days (paid), via `wrangler d1 time-travel restore`; (2) a weekly
`wrangler d1 export` written to a second R2 bucket, because Time Travel is a window and an export is
a real file; (3) migrations in git, so schema is always reconstructable even if data is not.
Backups contain ciphertext for `channel_credentials` — safe, provided `TOKEN_ENCRYPTION_KEY` is
stored somewhere other than the bucket. Restore drill happens once before v1.0, not during an outage.

**Timestamps.** Store `INTEGER` unix-ms UTC everywhere. `posts.schedule_at` is an absolute instant;
`workspaces.timezone` (default `Asia/Jakarta`) is used for display and for composing the slot, never
for comparison. Cron compares in UTC. This matters more than it looks: Instagram/Threads publish
*now*, so an off-by-one-hour bug is a post that goes out at the wrong time, not a cosmetic defect.

**Retention.** `activity_log` and `publish_results` are kept indefinitely (they are the audit
trail). Orphan media is purged only when unreferenced for 30 days and `postable = false`.

## 6. Integrations & APIs

| External | Purpose | Auth | Failure handling |
|---|---|---|---|
| Instagram Graph (`graph.instagram.com`) | publish + verify | long-lived Instagram user token per channel | container id stored on the job; `ERROR` → failed job; expired token → channel marked `reauth_required` |
| Threads (`graph.threads.com`) | publish + verify | Threads user token | same container pattern; 250 posts/24 h cap read from the API, not hardcoded |
| X (`api.x.com`) | media upload + post + verify | OAuth 1.0a user context | 402 → "top up credits", not retryable; chunked video upload, poll `processing_info` |
| TikTok | **not integrated** | — | `automatable: false`; product emits a manual upload pack (ADR-008) |
| Cloudflare R2 | media host | S3 SigV4 / Worker binding | upload failure blocks publish, never silently proceeds |
| Cloudflare Cron | job ticks | internal | a missed tick is harmless — the next one picks up the same queued rows |
| **Resend** | transactional email (verify, reset, publish-failure alert) | API key as a Worker secret | bounce/complaint webhook → `activity_log`; a failed reset is logged, never silently swallowed |
| **Turnstile** | bot defence on signup/reset | site key (client) + secret (Worker) | verification failure → uniform rejection, no hint about account existence |

**Long operations.** Instagram/Threads container polling can outlive a comfortable request. The
publisher stores the container id on the job and parks it as `awaiting_platform`; the next cron tick
polls again. Nothing depends on a Worker staying alive, because it cannot.

**Rate limiting.** Per-channel counters in D1 (one row per channel per minute window) plus
per-invocation guards. Instagram reads its own limit from `content_publishing_limit` before
publishing (Meta's docs give two different numbers; the endpoint is the truth). X is metered by
cost, so the estimate and spend cap do the work.

**Idempotency.** No platform here accepts a client-supplied idempotency key, so correctness comes
from our side: claim guard + `publish_results` pre-flight + unique index on `(variant_id)` where
`state = 'succeeded'`.

## 7. Security & Secrets

- **Secrets** are Worker secrets (`wrangler secret put`), never in `wrangler.toml`, never in git. A
  Zod schema validates them on first use — a missing key fails loudly with its name, not at 3am
  mid-publish.
- **Two different primitives, never confused.** *Passwords* are hashed by Better Auth (scrypt, pure
  JS, Workers-safe) — we never hand-roll a second scheme, and `argon2`/`bcrypt` are native addons
  that cannot load in `workerd`. *Platform tokens* are **encrypted** — WebCrypto **AES-256-GCM** —
  because we must replay them to Instagram/X, so they have to be recoverable. Hashing a token is a
  bug: a hash cannot be un-hashed, and no workaround makes it work.

- **Better Auth on Workers, three specifics that bite:**
  1. **Instantiate per request** with `env` — bindings exist only for the life of the invocation, so
     a module-level singleton captures a dead `env`. Lazy `getAuth()` per request, no exceptions.
  2. **Mount it once** at `/api/auth/*` via `auth.handler(request)` — the Web-standard handler, not a
     framework adapter. This is why Better Auth survives vinext being beta.
  3. **Trust the right IP header.** On Cloudflare only `cf-connecting-ip` is set by the edge;
     `x-forwarded-for`'s first hop is caller-controlled. Configure
     `advanced.ipAddress.ipAddressHeaders = ['cf-connecting-ip', 'x-forwarded-for']`, or rate
     limiting and the session audit are keyed on a value an attacker chooses.

- **Rate limiting is on, in the database.** `rateLimit: { enabled: true, storage: 'database' }` adds
  a `rateLimit` table in D1 — one more reason not to keep sessions in KV or memory. Login, signup and
  reset are the endpoints that matter; Turnstile sits in front of signup and reset.

- **Sessions**: DB-backed by Better Auth (no JWT-in-cookie), rotated on `updateAge`, revoked on
  password change, "sign out everywhere" available. Cookies are `HttpOnly, Secure, SameSite=Lax` by
  default; if OAuth is ever enabled, set `account.encryptOAuthTokens = true` — it is **off** by
  default.

- **Email (Resend)**: send from a subdomain (`mail.<domain>`) so a reputation hit cannot touch the
  root domain. Verify SPF + DKIM in DNS and add a DMARC record — without DMARC, password resets land
  in spam, which is worse than having no reset flow. Reset/completion tokens are single-use with a
  short TTL, and every auth response is uniform (no user enumeration: "if that address exists, a
  link is on its way").

- **Publishing kill switch (ADR-019).** `workspaces.publishing_enabled` plus a global
  `PUBLISHING_ENABLED` var, both checked at claim time. A wrong caption or the wrong account is
  stopped by a toggle, not a deploy; queued jobs stay queued and resume.
- **Platform tokens** live in `channel_credentials`, one row per channel: random 12-byte IV per
  write, `channel_id` bound in as **additionalData** so a ciphertext cannot be transplanted between
  rows. Key from `TOKEN_ENCRYPTION_KEY` (32 bytes, base64); `key_version` records which key
  encrypted the row, so rotation is a background re-encrypt rather than a flag day. Decryption
  happens only in the cron handler or a server action — **never** in a component, never in a
  payload sent to the browser, never in a log line.

  ```ts
  // src/lib/crypto.ts — the only place a secret becomes plaintext
  const key = await crypto.subtle.importKey("raw", b64(env.TOKEN_ENCRYPTION_KEY),
    { name: "AES-GCM" }, false, ["encrypt", "decrypt"]);
  const iv = crypto.getRandomValues(new Uint8Array(12));
  const ct = await crypto.subtle.encrypt(
    { name: "AES-GCM", iv, additionalData: enc(channelId) },
    key, enc(JSON.stringify(secret)));
  // store { ciphertext: ct, iv, key_version } — WebCrypto appends the GCM tag to ct
  ```

- **Lost key = re-auth, not data loss.** If `TOKEN_ENCRYPTION_KEY` is lost, every channel flips to
  `reauth_required` and the operator reconnects — the platform tokens are re-issued. Say this in the
  runbook; it is recoverable, unlike silently storing plaintext.
- **Tenant isolation** is application code (ADR-014) with a single chokepoint, a lint rule and
  cross-workspace tests. Recorded as the one guarantee that got weaker in the pivot.
- **Session cookies**: owned by Better Auth — `HttpOnly, Secure, SameSite=Lax`, signed with
  `BETTER_AUTH_SECRET`, DB-backed so revocation is real. No claims in the cookie; every request
  resolves session → user → membership server-side.
- **Authorization**: role checked per action (`viewer` cannot approve, `editor` cannot publish —
  PRD FR-01). Approval and publish are separate permissions.
- **Uploads**: MIME from magic bytes, never the extension or `Content-Type`; dimensions read with
  pure JS; **SVG rejected outright** (the vector behind the `sharp`/librsvg CVE). Metadata stripping
  happens client-side before upload; the server re-validates.
- **Secrets hygiene**: `.dev.vars`/`.env*` gitignored, no token in logs — redact `access_token`,
  `code`, `Authorization` before writing a line.
- **PII**: one email per user, nothing else. Deleting a user anonymises activity rows rather than
  deleting the audit trail.

### 7.5 What identity decided that the plan did not

Four things came out of building M1 that the original section could not have known:

1. **A fresh database has no user, and there is no public sign-up.** The door is
   `pnpm user:create <email> "<name>" [--remote]`, which writes the `user` and `account` rows with Better
   Auth's own scrypt hasher — the same function sign-in verifies with, so there is no second
   implementation to drift.
2. **The first account adopts the seeded workspace.** `ensureWorkspace` looks for a workspace with no
   memberships and claims it before provisioning anything. A solo tool seeds its tenant; asking the first
   user to invent one produced a name collision on `workspaces.name`, which is unique.
3. **Resolution is memoised per request (`src/auth/current.ts`).** A layout and a page that each resolved
   the session both saw "no workspace" and both tried to create one. `cache()` is the fix, and the
   negative lesson — an idempotent-looking helper is not idempotent until it is called twice at once —
   is the reason that file exists rather than a comment saying "be careful".
4. **Brand order is creation order, not alphabetical.** The first brand is the default; a default that
   moves when somebody renames a brand is a surprise.

## 8. Non-Functional Architecture

| Concern | Approach | Target |
|---|---|---|
| Performance | no cold start; batched D1 reads; board paginates at 50 cards; media from R2 CDN | p75 ≤ 1.2 s for 200 posts |
| Scalability | stateless Worker; the job claim is the only contention point; D1 single writer | 100 publishes/day at $0 |
| Observability | Workers Logs (JSON lines with `variant_id`/`job_id`); `activity_log`; `/api/health` | one log line per publish attempt |
| Portability | **deliberately single-vendor for MVP.** Export path: `wrangler d1 export` → SQLite → Drizzle schema port | porting to Postgres ≈ 2 days, recorded honestly |
| Reliability | claim guard, lease, retry ceiling, unique publish index, verify-after-publish | never double-post; ≥99% success ex-outages |
| Cost | D1 free, R2 free, Workers free → $5 paid only if CPU throttles | $0–5/mo + X per-post fees |
| Accessibility | semantic HTML, focus management on the board, 4.5:1 contrast from brand tokens | WCAG 2.2 AA |

**Cost model at expected volume** (one operator, two brands, ~40 posts/month):

| Resource | Expected use | Free allowance | Cost |
|---|---|---|---|
| D1 rows written | ~300/day | 100,000/day | $0 |
| D1 rows read | ~5,000/day | 5,000,000/day | $0 |
| D1 storage | < 20 MB (text only) | 500 MB | $0 |
| R2 storage / egress | < 1 GB / small | 10 GB / $0 egress | $0 |
| Worker requests | ~2,000/day | 100,000/day | $0 |
| Worker CPU | SSR pages | 10 ms per invocation | **$5/mo** if exceeded |
| X posts with a link | ~20/month | none (pay-per-use) | ~$4/mo |

So the honest floor is **$0 if SSR stays under 10 ms CPU, $5 if it doesn't**, plus X. Everything else
is free by a wide margin — the plan is sensitive to CPU, not to data volume.

## 9. Environments & Tooling

| Env | Purpose | Provisioning |
|---|---|---|
| dev | local development | `wrangler dev` with **local D1** (Miniflare state on disk) + local R2 binding — no Docker, no local Postgres, no network |
| CI | typecheck, lint, unit tests | Vitest in `@cloudflare/vitest-pool-workers`; migrations applied to a throwaway D1; no platform APIs |
| staging | smoke test against a private IG/X test account | separate D1 database + `*.workers.dev`; test tokens via `wrangler secret` |
| release | operator's real brands | D1 prod + R2 prod + custom domain; `wrangler deploy` + `wrangler d1 migrations apply --remote` |

```bash
# run from apps/frontend — the project root, where package.json and pnpm-lock.yaml live
pnpm install
pnpm dev                              # next dev today; vite dev after `vinext init`
pnpm exec vinext check                # once vinext is installed
pnpm typecheck && pnpm lint && pnpm test
pnpm db:migrate:local                 # wrangler d1 migrations apply --local
pnpm exec wrangler deploy
```

**Three pnpm 10 / Next 16 traps, all hit on first install:**

| Trap | Symptom | Fix |
|---|---|---|
| pnpm 10 blocks postinstall scripts by default | `wrangler` cannot start — `workerd`'s binary was never fetched | `pnpm.onlyBuiltDependencies: [esbuild, workerd]` in `apps/frontend/package.json` |
| `LayoutProps` / `PageProps` are **generated** types in Next 16 | bare `tsc --noEmit` fails with `Cannot find name 'LayoutProps'` on a clean checkout | `typecheck` script is `next typegen && tsc --noEmit` |
| Turbopack cannot follow a store outside its filesystem root | `pnpm dev` returns **HTTP 500** with a blank page; log says `Could not find the Next.js package (next/package.json)` and `ENOENT ... .next/dev/server/pages/_app/build-manifest.json` | only bites in a workspace, where pnpm puts the store above the app: `turbopack: { root: <workspace root> }`. **Not needed today** — the standalone store is inside the app, verified serving 200 |

The third one is the subtle one, and it is the one that argues for the current layout: in a workspace,
pnpm links `next` into a store above the app and Turbopack refuses to follow symlinks past its root,
so it stops recognising the framework it is running. **The wrong fix is a hoisted `node-linker`** — it
silences the error and removes the install-time enforcement of the layering boundary.

**Workers Builds topology.** The Worker's root directory is **`apps/frontend`** — which is also where
`package.json`, `pnpm-lock.yaml` and `wrangler.jsonc` live, so install, build and deploy all run in
the same directory.

| Setting | Value | Why |
|---|---|---|
| Root directory | `apps/frontend` | lockfile, wrangler config and build output are all here |
| Install | implicit `pnpm install` | the lockfile is in the directory the build runs from; nothing to walk up to |
| Build command | `pnpm run build` | cwd is already the project |
| Deploy command | `pnpm exec wrangler deploy` | wrangler finds `wrangler.jsonc` in cwd |
| Build watch paths | `apps/frontend/**` | the whole project sits under this path; extend it only when a second directory appears |
| `packageManager` | in `apps/frontend/package.json` | one declaration, in the directory that installs |

Two consequences worth stating because they are easy to get wrong:

- There is **no** `package.json` or `pnpm-lock.yaml` at the repository root. A root lockfile would be a
  second, unused source of truth that drifts from the one CI uses.
- Do not reintroduce `pnpm-workspace.yaml` at the root as a convenience. It silently pulls the app into
  a workspace, moves the store back above it, and re-triggers the Turbopack failure above.

`wrangler.toml` — the bindings are the whole architecture in 20 lines:

```toml
name               = "postvyn"
main               = ".vinext/worker/index.js"   # confirm against vinext 1.x build output
compatibility_date = "2026-11-01"
compatibility_flags = ["nodejs_compat"]

[[d1_databases]]
binding         = "DB"
database_name   = "postvyn"
database_id     = "<from `wrangler d1 create postvyn-db`>"
migrations_dir  = "db/migrations"

[[r2_buckets]]
binding     = "MEDIA"
bucket_name = "postvyn-bucket"

[triggers]
crons = ["* * * * *"]                            # the job tick; 1-minute granularity

[vars]
SPEC_VERSION = "1"
```

Secrets are **not** here — `wrangler secret put` only. A secret in `[vars]` is a secret in git.

## 10. Architecture Decision Records

| # | Decision | Choice | Alternatives considered | Rationale |
|---|----------|--------|-------------------------|-----------|
| ADR-001 | Runtime topology | One app, no separate API service, no second language | Next + Go service | two runtimes double ops surface for zero benefit at this load; Go stays available behind the `Publisher`/`jobs` seam |
| ADR-002 | *(superseded by ADR-013)* | Postgres + Drizzle | — | Neon scale-to-zero made the first request after idle unacceptable |
| ADR-003 | *(superseded by ADR-014)* | Postgres RLS for tenancy | — | D1 has no row-level security |
| ADR-004 | Job execution | `jobs` table + cron tick | long-lived worker, external queue | no always-on process on Workers (amended by ADR-015) |
| ADR-005 | Publishing trigger | Verify-after-publish with stored `publish_results` | trust the API response | PRD FR-08; a 200 is not a live post |
| ADR-006 | Approval binding | Content hash on the approval | approve-by-status only | an edit after approval must invalidate it; status cannot express that |
| ADR-007 | Agent interface | `{ok, result, log}` envelope on every mutation, mirroring the v0.1 CLI | REST-purist resource API, GraphQL | the existing CLI already speaks it; agents need intent verbs and a trace, not CRUD |
| ADR-008 | TikTok | No adapter; manual pack only | build an uploader | their Content Sharing Guidelines name this exact use case as unacceptable; unaudited clients post `SELF_ONLY` |
| ADR-009 | Media storage | R2 with content-hash keys + public read bucket | DB blobs, per-tenant signed URLs | platforms fetch URLs unauthenticated; hashing dedupes and makes retries free |
| ADR-010 | UI components | Local shadcn-pattern files, no UI dependency | MUI, Chakra, published design system | brand theming is CSS variables from `brand.json`; a dependency fights that |
| ADR-011 | Credentials at rest | AES-256-GCM in `channel_credentials`, key from Worker secret, per-row IV + `channel_id` as AAD, versioned keys | bcrypt/Argon2 hashing, plaintext, per-user secrets file, external vault | tokens must be replayed, so they must be decryptable — hashing is impossible here; a separate table keeps ciphertext out of ordinary selects; versioned keys allow rotation |
| ADR-012 | Account cardinality | Credentials belong to a **channel**, and a brand may hold many channels per platform | one credential set per user, one account per platform | one person runs several brands and several accounts; tying secrets to a user forces sharing and makes revocation all-or-nothing |
| **ADR-013** | **Database** | **Cloudflare D1 (SQLite)** | Neon/Postgres, Turso, self-hosted PG | no cold start, no idle billing, zero ops; SQLite is sufficient for text-only rows at this volume |
| **ADR-014** | **Tenancy** | **Scoped repository + lint rule + cross-workspace tests** | RLS (unavailable in D1), per-tenant database (overkill), client-supplied workspace id (unsafe) | the guarantee is weaker than RLS and is recorded as a known downgrade rather than papered over |
| **ADR-015** | **Job claim** | **Single-statement claim guarded by state, on D1's single writer** | `SKIP LOCKED` (absent in SQLite), Durable Object singleton (second primitive), Queues (paid) | one writer means claims serialize; `RETURNING *` with zero rows = someone else won |
| **ADR-016** | **Framework path** | **vinext 1.x (Next API on Vite), Workers target** | Next + OpenNext adapter, Next on a VPS, drop Next for Astro/Hono | Cloudflare's default path since Sept 2026 and what C3 scaffolds; OpenNext lags Next 16 |
| **ADR-017** | **Auth** | **Better Auth 1.7.x for identity only** — `user`/`session`/`account`/`verification` in D1; `workspaces`/`memberships` remain our authorization model | hand-rolled sessions, Auth.js (now part of Better Auth), Clerk, Better Auth's organization plugin for tenancy | framework-agnostic `Request`→`Response` handler is exactly what a beta framework needs — no `next/headers` coupling; `vinext check` confirms it uses only public `next/*` APIs. Verification/reset/rate-limit/2FA come free. Organization plugin rejected: our approve-vs-publish split is product logic, and two tenancy models is the failure mode ADR-014 already compensates for |
| **ADR-018** | **Image handling** | **Pure-JS dimension/MIME checks, client-side metadata strip, no `sharp`** | sharp (native, cannot run), Cloudflare Images (paid), `@jsquash` WASM | avoids a native dependency and the librsvg/SVG CVE class entirely |
| **ADR-019** | **Kill switch** | `workspaces.publishing_enabled` + global `PUBLISHING_ENABLED` var, checked at claim time | deploy-to-stop, manual job deletion | a wrong caption or a wrong account needs to be stoppable in one click, not one deploy; queued jobs survive and resume when re-enabled |
| **ADR-020** | **Email** | **Resend**, from a dedicated sending subdomain | Cloudflare Email Workers, SES, Postmark, no email | free tier covers one operator; the only emails that matter in v1 are reset, verification and publish-failure alerts |

## 11. Implementation Guidance

**Build order** (each step ends with something demonstrable):

1. `wrangler` project + `vinext init --platform=cloudflare`; run `vinext check` and read the
   compatibility report **before** writing app code.
2. `src/db` — Drizzle schema for SQLite + first migration + the scoped-repository chokepoint.
3. Cross-workspace isolation test (seeds A and B, asserts B is invisible from A) — this replaces the
   RLS gate from v0.1 and is the M0 exit criterion.
4. `src/lib` — status machine, spec engine, approval hash, WebCrypto helpers. Unit tests first;
   this module is the product and must be provable without a browser.
5. `apps/frontend` — session auth, workspace resolution, brand switcher, read-only board.
6. Importer from the v0.1 vault, then the composer and variants.
7. Approvals + `jobs` + cron handler (dry-run mode wired from day one).
8. `src/publishers` — one platform at a time, in this order: Threads (simplest), Instagram,
   X (cost + chunked upload).
9. Media library and R2 signed uploads.
10. Manual pack for TikTok; cutover from the vault.

**Importer contract (M2 — the step most likely to lose data, so it is specified here, not improvised
during the build):**

- **Input** is a queue folder per platform: `brands/<brand>/social/<platform>/queue/<id>/` holding
  `item.json`, `caption.md`, and assets. One folder = **one post + one variant**.
- **Status** is copied verbatim, including `schedule.at` and any `publish` block (which becomes
  `publish_results` rows). Nothing is "cleaned up" on the way in — an import dispute is worse than an
  ugly field.
- **Assets** are hashed (sha256), uploaded to R2 in the same pass, and referenced by key. A re-run
  reuses the same hash, so retries are free and never duplicate bytes.
- **Idempotent**: the natural key is `(brand, platform, id)`; a second run updates rather than
  duplicating. This matters because the vault keeps changing while the app is being built.
- **Dry run is the default.** The importer prints a diff report — folders seen, rows written, per-field
  mismatches — and refuses to commit on any mismatch unless `--force` is passed with a reason that is
  written to `activity_log`.
- **Review artifacts** (`contact-sheet*`, `thumb*`, `preview*`) are imported as `media.postable=false`
  so they exist as history but can never be attached to a publish.

**Gotchas already paid for in v0.1 — do not rediscover them:**

- `caption.md` headings need `re.MULTILINE`; a naive `^## Caption` anchor matches at string start
  only and silently parses every caption as empty. Validate "caption non-empty" as a hard error.
- `item.json` asset lists include review artifacts (contact sheets, thumbnails). Filter them or the
  platform receives a grid of frames.
- Instagram and Threads have **no scheduling endpoint** — the API publishes *now*. The job must run
  at the slot; there is no "post later" parameter to lean on.
- Re-approving to a new slot when the status is already `approved` must still persist. A
  status-only write is a no-op.
- X counts any link as $0.20, including a bare domain in the text. Estimate conservatively.
- Instagram needs media on a publicly fetchable URL; Meta curls it. Localhost will not work.
- A missing `--platform` on an id that exists on four platforms must be an error, not a guess.

**New traps introduced by this stack:**

- **50 D1 queries per invocation on the free plan.** An N+1 loop blows the budget silently — the
  board fetches in one batched read.
- **No interactive transactions.** `db.batch()` or idempotency; there is no `BEGIN…COMMIT` across
  `await`.
- **`sharp`, `resvg`, `satori`, `lightningcss`, `@napi-rs/canvas` fail under vinext dev.** Do not
  reach for them; if image work grows, use WASM (`@jsquash`) or Cloudflare Images.
- **Cache Components / `"use cache"` are incomplete in vinext.** Do not use them — for correctness
  *and* because that surface carries the October 2026 RCE history.
- **A Worker cannot outlive a request.** Any platform call longer than a few seconds becomes
  `awaiting_platform` and resumes on the next tick.
- **vinext is 1.0 but young.** Run `vinext check` after every dependency bump and keep the Next-shaped
  code boring: App Router, route handlers, server actions, no exotic `next/*` internals.

**Test strategy per layer.** `src/lib`: pure unit tests, table-driven over spec fixtures.
`src/publishers`: recorded HTTP fixtures (happy path, expired token, 402, container `ERROR`),
asserting the adapter never calls a real host. `apps/frontend`: one test per endpoint on the envelope
shape, plus cross-workspace denial. Nothing in CI may require credentials.

## 12. Glossary

| Term | Definition |
|---|---|
| **vinext** | Cloudflare's Vite-based reimplementation of the Next.js API; primary target is Workers |
| **D1** | Cloudflare's SQLite database, accessed as a Worker binding; single writer |
| **Brand / profile** | a person or company with its own voice, colours and channels |
| **Channel** | one connected platform account under a brand |
| **Workspace** | tenant boundary; the value every query is scoped by |
| **Variant** | the per-platform rendering of a post; the unit that publishes |
| **Spec rule** | versioned platform limits (sizes, caption max, hashtags, media caps) |
| **Approval hash** | fingerprint of a variant at approval time; mismatch blocks publishing |
| **Job** | a durable D1 row describing work to do; claimed by a cron tick under a lease |
| **Lease** | time-bounded claim on a job, so a dead invocation's work is recoverable |
| **`awaiting_platform`** | job state for long platform processing that resumes on a later tick |
| **Publisher port** | the single interface every platform integration implements |
| **Manual pack** | generated upload sheet for platforms with no automatable path |
| **Envelope** | `{ok, result, log}` — the shape every mutation returns to UI and agents |
| **Scoped repository** | the single module allowed to touch D1, which requires a `WorkspaceContext` |
