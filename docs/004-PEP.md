# Project Execution Plan — Postvyn

**Version:** 0.1
**Date:** 2026-Nov-15
**Status:** Draft
**Derived from:** PRD v0.1 (`docs/001-PRD.md`), ITA v0.1 (`docs/003-ITA.md`)

---

## 1. Project Overview

Deliver v1.0 of Postvyn — a multi-profile publishing workspace you run yourself on Cloudflare — by
mid-January 2027, replacing the vault-based v0.1 without losing a single post of history. The
single biggest risk is not technical: it is that one person builds this between client work, so
the plan is sized to slip gracefully rather than to look ambitious.

| | |
|---|---|
| **Target release** | v1.0 — 2027-Jan-10 (v0.2 parity 2026-Dec-02) |
| **Delivery mode** | solo builder (Uwi) + agent-assisted implementation |
| **Overall confidence** | medium — the stack is proven and the rules already exist; credentials and calendar are the variables |

## 3. Milestones & Phases

| Phase | Deliverable | Duration | Exit criteria | Status |
|-------|-------------|----------|---------------|--------|
| **M0 — Foundations** | monorepo, CI, `src/db`, scoped repository, env schema | ~4d | cross-workspace isolation test green in CI; `vinext check` clean; a missing secret fails loudly | ⬜ |
| **M1 — Identity** | auth, workspaces, memberships, brands | ~4d | two workspaces see only their own brands; `editor` gets 403 on publish | ⬜ |
| **M2 — Parity** | vault importer + read-only queue board | ~5d | the vault's live items appear with identical status, schedule and publish records | ⬜ |
| **M3 — Authoring** | composer, variants, spec engine | ~5d | counter matches platform counting (X URLs = 23); spec errors block; warnings name the override | ⬜ |
| **M4 — Control** | approvals (hash-bound), `jobs`, worker, dry-run | ~4d | an approved post fires with the laptop closed; a duplicated claim cannot double-post | ⬜ |
| **M5 — Shipping** | Threads → Instagram → X adapters, TikTok manual pack | ~5d | one real post per platform, read back and verified; TikTok produces the pack, not an upload | ⬜ |
| **M6 — Cutover** | media library, polish, retire vault publishing | ~3d | a full week ships from the app only; `tools/publish` becomes read-only history | ⬜ |

**Total: ~30 working days across ~8 calendar weeks** (holiday drag in late December included).

## 4. Work Breakdown

### M0 — Foundations
- [ ] `git init`, pin pnpm in `apps/frontend`; `vinext init --platform=cloudflare` then read the `vinext check` report — ~4h
- [ ] CI: typecheck + lint + test on push, no platform credentials — ~3h
- [ ] `src/db`: Drizzle schema for SQLite + `wrangler d1 migrations` — ~1d
- [ ] Scoped repository (`WorkspaceContext`) + lint rule banning raw `db(` outside `src/db` — ~1d
- [ ] Cross-workspace isolation test: seed A and B, assert B is invisible from A — ~4h
- [ ] Env/secret schema (Zod) + `.dev.vars.example` + first-use validation — ~2h
- [ ] Local dev sanity: `wrangler dev` + local D1, no Docker — ~2h

### M1 — Identity
- [ ] Better Auth: `@better-auth/cli generate` → Drizzle → `wrangler d1 migrations`; mount `auth.handler` at `/api/auth/*`; per-request instance — ~1d
- [ ] Resend: verify the `mail.` subdomain (SPF/DKIM/DMARC), wire verification + reset callbacks — ~4h
- [ ] Turnstile on signup + reset — ~2h
- [ ] Auth events into `activity_log` (login, failed login, reset, revoke-all) — ~2h
- [ ] Workspace + membership model, invite flow (email link, role fixed at invite) — ~1d
- [ ] Brand CRUD with colours/voice/handle + theme tokens into CSS variables — ~1d
- [ ] Role guard middleware + endpoint tests (`viewer`/`editor`/`owner`) — ~4h
- [ ] **Start the Meta app now** (Instagram + Threads tester), X dev account + credits — ~2h

### M2 — Parity
- [ ] Vault importer: folder → post + variant, verbatim, with a dry-run diff report — ~1.5d
- [ ] Queue board: status columns, counts, channel/pillar filters, pagination — ~1.5d
- [ ] Card detail: caption preview, hashtags, asset list, spec verdict — ~1d
- [ ] Import verification: row counts + per-field diff against `item.json` — ~4h

### M3 — Authoring
- [ ] Spec engine as versioned data + validator + unit tests (table-driven) — ~1d
- [ ] Composer: caption, hashtag buckets per platform, live counter — ~1.5d
- [ ] Variant model: N variants per post, per-variant media order — ~1d
- [ ] Draft autosave (5 s debounce) + conflict handling — ~4h
- [ ] Warnings/overrides with a typed reason, written to `activity_log` — ~3h

### M4 — Control
- [ ] Approval: hash computation, storage, invalidation on edit — ~1d
- [ ] `jobs` table + single-statement claim guarded by state + lease expiry — ~1d
- [ ] Cron-trigger handler invoking the same claim loop (no long-lived worker) — ~2h
- [ ] `awaiting_platform` state for container polling across ticks — ~2h
- [ ] Double-publish test: two concurrent ticks, one job, one post — ~3h

### M5 — Shipping
- [ ] Threads adapter (container → poll → publish → verify) — ~1d
- [ ] Instagram adapter (REELS/IMAGE/CAROUSEL, media on public URL) — ~1.5d
- [ ] X adapter (chunked video upload, cost estimate, 402 handling) — ~1.5d
- [ ] TikTok manual pack generator (caption + hashtags + asset + checklist) — ~3h
- [ ] Recorded fixtures for expired token, container `ERROR`, 402, rate limit — ~3h

### M6 — Cutover
- [ ] R2 signed upload, MIME sniff + `sharp` re-encode, dedupe by hash — ~1d
- [ ] Manual pack surfaces in the post view, completion recorded — ~3h
- [ ] Runbook: connect a new channel, rotate a token, recover a failed job — ~3h
- [ ] One full week shipped from the app; then freeze `tools/publish` — ~2h + observation

## 6. Risk Register

| # | Risk | Likelihood | Impact | Mitigation | Trigger to act |
|---|------|-----------|--------|------------|----------------|
| R1 | Sole builder: client work displaces build time | H | H | fixed Monday slot; scope ladder below; milestones are independently shippable | two weeks with no milestone progress |
| R2 | Meta app / tester setup takes longer than expected | M | H | start in M1, not M5; adapters have fixtures so the board is testable without credentials | credentials absent by start of M5 |
| R3 | RLS bug leaks another tenant's rows | L | H | isolation test is an M0 gate; `workspace_id` never from request input; second review on any policy change | any test that passes with the setting absent |
| R4 | Scope creep back into "a full CMS" | H | H | PRD §5 out-of-scope list is the contract; anything new needs a PRD amendment first | a task that is not in §4 of this doc |
| R5 | X billing surprises | L | M | spend cap per workspace, cost shown pre-publish, dry-run default | any 402 |
| R6 | Next.js security advisory lands mid-build | M | M | pinned floor `>=16.4.5`, dependabot on, upgrade window in the buffer week | advisory names our version range |
| R7 | Import loses or mangles history | L | M | verbatim importer + field-level diff; nothing "cleaned up" during import | diff report shows any field drift |
| R8 | Publishers only tested against live accounts late | M | H | fixtures from M4; live smoke in M5 with one private account first | first live post fails on auth |
| R9 | Operator review becomes the bottleneck (visual QA is human-only) | M | M | briefs are numbered and batchable; review happens once per week, not per post | approval queue older than 7 days |
| **R10** | **vinext is 1.0 but young** — a Next-shaped pattern we rely on turns out to be a compatibility gap | M | H | `vinext check` in CI on every bump; keep to App Router / route handlers / server actions; no Cache Components; the v0.1 CLI stays runnable as a fallback shipper | `check` reports a gap in code we already wrote |
| **R11** | D1 free-tier ceilings (50 queries/invocation, 100k writes/day) surprise us | L | M | batched reads by design; a query-budget test on the board endpoint; moving to Workers Paid ($5) removes the per-invocation query cap | any 429/"too many queries" error in staging |
| **R12** | Better Auth churn — and the false assumption that core, adapter and CLI share a version | M | M | pin `better-auth` + `@better-auth/drizzle-adapter` **together** (1.7.x); `@better-auth/cli` lives on its **own 1.4.x line** and bundles older core + drizzle copies (dev-only advisories — ITA §3). Regenerate schema deliberately; our tables never reference their internals | a migration diff touching Better Auth tables we didn't intend, or a CLI schema that disagrees with core |
| **R13** | Auth email lands in spam, so reset looks broken | M | M | dedicated sending subdomain + SPF/DKIM/DMARC from day one; test reset against Gmail and Outlook before M1 exits | a reset email not arriving in a real inbox |

**Scope ladder (what gets cut, in order, when R1 fires):**

1. Draft autosave → manual save button.
2. Calendar view (already out of v1.0) → stays out.
3. Carousel support → single-media only for v1.0.
4. X adapter → manual copy-paste, like TikTok.
5. Media library UI → upload on the composer only.

Never cut: RLS, approval binding, spec gate, verify-after-publish, the TikTok refusal.

## 7. Quality & Testing Strategy

| Level | What | Tool | Gate |
|-------|------|------|------|
| Unit | spec engine tables, status machine, approval hash, cost estimate | Vitest | 100% of `src/lib` rules; red on any uncovered rule |
| Integration | route handlers on the `{ok, result, log}` envelope; cross-workspace denial | Vitest in `@cloudflare/vitest-pool-workers` (real `workerd` + local D1) | no merge with a failing envelope test |
| Adapter | IG/Threads/X against recorded fixtures (happy, expired token, `ERROR`, 402) | Vitest + nock | no real host in CI, ever |
| Concurrency | two concurrent cron ticks, one job → one publish | Vitest + two claim calls on the same row | must pass before M4 exits |
| E2E | board → composer → approve → mock publish | Playwright | one happy path, one permission-denied path |
| Manual | visual QA of renders; first live post per platform | Uwi + dashboard | human sign-off; the agent never claims to have seen an image |

Green gates before any merge: `typecheck`, `lint`, `test`. Before any milestone exit: the whole
table above.

## 8. Release Plan

- **Channels:** `wrangler deploy` to `*.workers.dev` then a custom domain. No public package, no app store.
- **Versioning:** `0.x` until v1.0; then semver, with the envelope and DB schema treated as the
  public contract.
- **Rollout:** staging (private test accounts) → prod with one brand → all brands. One week of
  dual-run against the vault is allowed; publishing stays single-source (app) even during it.
- **Rollback:** redeploy the previous build, then pause the worker (`WORKER_ENABLED=false`). Jobs
  stay queued, nothing is lost; a partial publish is visible in `publish_results` and reconciled
  by hand. Database migrations are additive for the duration of each milestone so a rollback never
  needs a down-migration.
- **Cutover:** the vault keeps its files as history; `tools/publish` stops accepting new
  approvals on the day M6 closes.

## 10. Change Control

1. A new request is written as a one-line amendment to the PRD (§5 scope or §7 FRs), never as a
   silent code decision.
2. Impact is assessed against §4 and the timeline in §5; the cost is stated in days.
3. Uwi approves or defers. Deferred items go to the PRD's open questions, not into the backlog
   where they quietly become commitments.
4. This document is then updated in the same session: phase table, work breakdown, timeline.
   The plan and the PRD must never disagree about what is in v1.0.

## 11. Assumptions, Dependencies, Constraints

| Type | Statement | If false |
|------|-----------|----------|
| Assumption | Cloudflare D1 + Workers + R2 free tiers cover a solo operator's volume | move to Workers Paid ($5) or tighten queries; cost changes, code does not |
| Assumption | Meta Standard Access (own accounts only) is enough for v1 — no App Review | v1 slips behind a review queue; board and importer still ship, publishing waits |
| Assumption | ~4–6 h/day of build capacity, ~2 h/week of operator review | extend the timeline week-for-week; never compress the review gate |
| Dependency | Instagram account is Business/Creator; Threads account can be added as a tester | adapters are blocked at smoke test; fixtures still let M5 code complete |
| Dependency | X dev account has prepaid credits | X demoted to manual (scope ladder step 4) |
| Dependency | v0.1 remains stable enough to import from during M2 | freeze `tools/publish` early and import from a git tag |
| Constraint | Single builder, no paid help | every milestone must be independently shippable |
| Constraint | $0–5/month running cost | no managed queue, no paid observability, no paid image service |
| Constraint | TikTok is never automated (ToS) | product scope changes, not the plan |
