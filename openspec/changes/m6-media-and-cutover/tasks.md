- [x] 1.2 `POST /api/v1/media/:id/record` writes the media row after the upload, verifying size and MIME server-side — `src/app/api/v1/media/[id]/record/route.ts` (+ `/api/agent/media/[id]/record`); `record()` in `src/db/media-upload.ts` re-reads the object from R2 by `head` + `get` and trusts none of the client's claims; "records the stripped bytes: size, hash and dimensions come from the object" and "refuses a declared type the bytes disagree with, and keeps nothing" in `test/intake.test.ts`
- [x] 1.3 Magic-byte sniffing for PNG, JPEG, WebP, GIF, MP4, MOV — and an explicit refusal for SVG — named `MAGIC` table + ISO-BMFF brand check in `src/lib/media/bytes.ts`; SVG is recognised through a prolog/comment prefix too and refused with the script-container reason at mint and at record; "the sniffer trusts bytes, not names" (10 cases) in `test/media.test.ts`
- [x] 1.4 Strip EXIF before the object is retrievable; re-read the stripped object to confirm — `stripMetadata()` drops JPEG APP1–APP15 + COM, PNG `tEXt`/`zTXt`/`iTXt`/`eXIf`, WebP `EXIF`/`XMP `; `record()` asserts the strip is idempotent and `store()` HEADs the object to prove the stored size is the stripped size; video is stored as uploaded (re-muxing is a non-goal — stated in the file); "drops a JPEG's APP1 segment…", "drops a PNG's tEXt chunk…", "strips EXIF before the object is retrievable" tests
- [x] 1.5 Compute the content hash on the stripped bytes so dedupe reflects what is actually stored — `sha256Hex(stripped)` in `src/db/media-upload.ts`; the key, the `media.hash` column and the dedupe lookup all use it; asserted against `sha256Hex(stripMetadata(PNG))` in `test/intake.test.ts`
- [x] 1.6 Deduplicate on `(workspace_id, hash)`: return the existing row and URL instead of writing twice — index `one_media_per_hash_per_workspace` already existed (no migration); `record()` looks up first, deletes the landing object, and `onConflictDoNothing().returning()` makes a concurrent race resolve to the winner's row; row id is now hash + random suffix because a hash-only id collided across workspaces (spec: two workspaces never share a row); "the same bytes are stored once per workspace" (3 tests) in `test/intake.test.ts`
- [x] 1.7 Record dimensions without a native image library — `dimensions()` walks PNG IHDR, JPEG SOFn and the GIF screen descriptor in pure JS; WebP and video record null with the reason stated in the file (no spec rule needs video pixels, and a `moov` walk is not cheap); client-declared dimensions are compared and refused on disagreement, never stored — "refuses dimensions the header does not have…" in `test/intake.test.ts`
- [x] 1.8 Refuse an upload larger than the configured ceiling before minting a URL, not after — `MAX_UPLOAD_BYTES` (25 MB, `docs/003-ITA.md` §8) in `src/lib/media/bytes.ts`, checked in `mint()` before signing and re-checked in `record()` against `head.size`, where the object is deleted; "refuses an oversize file before a URL exists — even with no storage configured" and "refuses an object above the ceiling that a client ignored" tests

## 3. Hygiene

- [x] 3.1 Purge sweep: non-postable media and unreferenced objects past the retention window — `src/db/media-purge.ts`: a candidate is `postable = 0` **and** older than `MEDIA_RETENTION_MS` (30 days, `docs/003-ITA.md` §5 "Retention") **and** named by no variant's `media_ids`; plus any `media/<workspace>/` object no row names (an unrecorded upload, a deleted workspace's leftovers). Row first, object second, so a half-delete never leaves a row pointing at a 404; "deletes a non-postable row and its object once it is past the window", "deletes an object no row names, once the window has passed", "leaves a postable asset alone even when nothing references it" in `test/media-purge.test.ts`
- [x] 3.2 Dry-run mode listing exactly what would be deleted, with sizes — same code path, `mediaPurge(env).sweep(ctx, { dryRun: true })` / `runMediaPurge(env, { dryRun: true })` answers `{ reason, key, bytes }[]` and deletes nothing; the plan is logged in one line in both modes ("deletion is recorded before it happens"). No route: `003-ITA.md` §4.3 lists no purge surface and no runbook step needs one, so the operator entry point is the function; "lists the same keys and sizes and deletes nothing", "records the plan before it deletes, and says nothing when there is nothing to do" in `test/media-purge.test.ts`
- [x] 3.3 Never delete media referenced by a variant; never delete published media — both asserted by test — the reference check runs in the listing *and* again inside the `delete`, so a variant that gains the media between the two keeps its bytes (the row is reported `skipped`, never `deleted`); a published post's media is its variant's media, and the variant is what the check reads — "leaves media a variant still points at, however old it is", "leaves the media of a published post alone" in `test/media-purge.test.ts`
- [x] 3.4 Run the sweep on the cron trigger, beside the publish tick — second cron `"0 3 * * *"` in `wrangler.jsonc`, matched against `HYGIENE_CRON` (`src/db/scheduled.ts`) in `src/worker.ts`'s `scheduled` so `runMediaPurge` runs instead of `runScheduled`; daily because the window is days, and an idle sweep logs nothing — "runs over every workspace on the cron", "…and says nothing when there is nothing to do" in `test/media-purge.test.ts`
